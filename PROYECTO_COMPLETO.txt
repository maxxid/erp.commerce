1. QUÉ HACE
================================================================================
Sistema para kioscos/almacenes que permite escanear un código de barras,
buscar el producto en Carrefour (API VTEX), Vea y Masonline (scraping HTML),
extraer nombre, marca, precio, foto, propiedades nutricionales, y guardarlo
en una base SQLite local con precio de venta calculado (margen + redondeo).

Características:
- Lookup por código de barras desde 3 fuentes (Carrefour API, Vea HTML, Masonline HTML)
- Comparación de precios entre las 3 fuentes (badges)
- Detección de promociones/descuentos
- Categorización automática
- Precio de venta = precio_referencia * (1 + margen%) redondeado
- CRUD de productos (editar, eliminar)
- Exportación CSV/JSON
- Dashboard con totales y valor del stock

3. CÓMO FUNCIONA EL LOOKUP
================================================================================
1. Usuario escanea código de barras (o tipea)
2. Enter -> POST /api/lookup { barcode }
3. Backend busca en DB local primero (obtener_por_barcode)
4. Si no está en DB:
   a. Busca en Carrefour API (1-2 segundos)
   b. Si no encuentra -> Vea scraping (3-5 segundos)
   c. Si no encuentra -> Masonline scraping (3-5 segundos)
5. Devuelve JSON con producto + fuente
6. Frontend renderiza tarjeta con datos
7. Mientras tanto, en paralelo, busca en las otras fuentes para comparar precios
8. Badges se actualizan individualmente cuando llega cada respuesta
9. Usuario ajusta cantidad, precio venta, categoría y guarda

4. REGLAS DE NEGOCIO
================================================================================
- Precio venta = Math.ceil(precio_referencia * (1 + margen/100) / redondeo) * redondeo
- Margen default: 30%, Redondeo default: $50
- Si producto ya existe en DB (por codigo_barras), se actualiza (UPSERT)
- Categorías se auto-asignan desde VTEX con mapping fijo
- Categorías nuevas se persisten en config y re-aparecen en selects
- El toggle "Analizar con IA" es placeholder (no hace nada todavía)

6. PROBLEMAS CONOCIDOS
================================================================================
- Carrefour API puede rate-limit (cambia poco)
- Vea/Masonline: si cambian estructura HTML, el scraping rompe
- __STATE__ parsing es frágil (busca llaves { } manualmente)
- No hay autenticación (es local/single-user)
- No hay logging estructurado
- Las propiedades nutricionales a veces vienen vacías
- No hay manejo de timeouts diferenciado por fuente
